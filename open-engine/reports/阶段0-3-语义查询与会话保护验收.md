# 阶段 0-3：语义查询与会话保护验收

日期：2026-09-18

## 本阶段交付

- `FlowCorrelator`：按显式 `flowId`、`requestId`、父事件、值哈希和端点做可解释关联；不使用仅靠时间的猜测。
- `SessionGuard`：可选的会话 ID、活动会话、最大年龄、未来时间偏差、freshness 和 TTL 检查。
- `collect.Ingestor`：把 Guard → Correlator → Deduplicator → bounded index 串成单一入口。
- `host.Server`：嵌入式 MCP JSON-RPC Handler，支持 `initialize`、`tools/list`、`tools/call` 以及直接工具方法。
- `IDHHookRegistry`：Objective-C 侧 Profile 状态注册中心，支持原子安装和快照，但不执行 Hook。

## 面向 CMCC iOS/H5 问题的收益

同一个账号在不同层返回的结果不会再被简单归并成“下单失败”：

- `data.risk=true` 或 `SCORE_REFUSE` 会由 `classify_response` 标成 `risk_layer`。
- `resultCode=999` 且 `data` 为空会标成 `business_layer`，并记录“未出现 data.risk 判据”。
- 通过 `flowId/requestId/valueRefs` 可把 bridge、加密、网络请求和响应放进同一条流，再由 `summarize_flow` 输出给 AI。
- `SessionGuard` 可在导入旧 HAR、旧 cookie 或旧 bridge ticket 时显式拒绝，避免把离线证据误报成实时成功。
